## 先留下一个问题 {#question}

这是一篇**演示笔记**，不是你的真实研究成果。它用普通 Markdown 写成，用来展示文字、数学推导、图像和 HTML 文件如何互相连接。

写作时，先不急着把所有内容塞进同一个文档。这里负责记录问题，推导放在另一篇笔记里，交互式结果保留为独立文件。每一份材料都有自己的位置，也都有回到原处的路径。

> 文字留在笔记里，细节放进关联文件。阅读时可以走出去，但不必丢掉来时的思路。

你可以先[平滑滑动到这篇笔记的关联资料](#materials)，也可以通过左侧可收起的目录定位章节。手机上直接向下阅读即可。

## 建立一个最小的例子 {#example}

考虑下面的示例目标函数。它只用于演示数学排版，不代表任何真实实验。

$$
\mathcal{L}(\theta)
=\frac{1}{n}\sum_{i=1}^{n}(y_i-\theta x_i)^2.
$$

在正文里只保留定义，把求导过程放到另外一篇 Markdown 中：

[打开另一篇笔记，并定位到推导结论](02-derivation.md#result)。

点击后会进入下一篇笔记。页面右下角会出现一个大的 **“返回上一份文件”** 按钮。点击它，会返回本页并恢复刚才的阅读位置；页面短时间加载或窗口尺寸改变时，恢复位置可能有少量偏差。

你也可以从那篇推导继续打开 HTML 或 LaTeX 文件，再逐层返回。阅读路径会保存在当前浏览器标签页的会话中。

## 给记录留一点上下文 {#context}

一份可复查的记录，最好说明为什么需要这次分析、输入是什么、输出放在哪里。这样，再次打开这篇笔记时，不必依赖记忆重新寻找散落的文件。

这里使用以下组织方式：

| 内容 | 文件位置 | 阅读方式 |
|:---|:---|:---|
| 问题描述 | 当前 Markdown | 直接阅读 |
| 数学推导 | `02-derivation.md` | 跳转到指定章节 |
| 交互演示 | `files/response-surface.html` | 在文件阅读器内预览 |
| 公式源码 | `files/objective.tex` | 查看源码或下载 |
| 示例数据 | `files/example-data.csv` | 查看文本或下载 |

这些只是普通的相对路径。你仍然可以在 VS Code 中打开它们，不需要把 Markdown 转换成某种专用数据库。

## 回到问题本身 {#next}

关联文件的作用是帮助理解正文，而不是让阅读不断分岔。完成一次查看之后，点击右下角的大按钮回到上一个文件，再决定是否继续深入。

页面下方还有一个专用的**滑动阅读区域**：手机上在这块区域右滑返回，左滑打开本篇的第一个关联链接。普通正文、代码块和表格保留正常滚动，不会因为随手滑动而突然跳页。

把你的第一篇真实笔记放进 `notes/` 后，重新渲染网站，就可以替换掉这段演示。
